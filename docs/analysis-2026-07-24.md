## 一、myx 各阶段安全资产盘点

### Phase 2（环境优化）— 4 项可移植

| 资产 | 来源 | 详情 |
|------|------|------|
| **sysctl 安全参数** | `templates/system/sysctl-99-myx.tmpl` | 18 项安全保留参数：syncookies、rp_filter、ICMP redirect 禁用、source route 禁用、martian 日志等 |
| **sysctl 性能参数** | 同上 | BBR + TCP buffers(64MB) + fastopen + keepalive |
| **limits.conf** | `templates/system/limits-99-myx.tmpl` | nofile=1048576, nproc=65535 |
| **自动 swap** | `phase2_environment.go` | 小内存 VPS 自动创建，含磁盘空间检查 |

### Phase 3（核心）— 1 项高价值

| 资产 | 来源 | 详情 |
|------|------|------|
| **DNS 加固 + chattr +i** | `internal/service/dns.go` | 8.8.8.8+1.1.1.1 置顶，`chattr +i` 防 DHCP/cloud-init 覆盖，卸载时恢复 |

### Phase 5（运维）— 5 项可移植

| 资产 | 来源 | 详情 |
|------|------|------|
| **智能防御框架** | `defense.go` + phase5 | ipset + geoip + iptables/UFW 联动，国外IP直接封，国内IP限速 |
| **Fail2ban web 扫描器过滤** | `fail2ban-filter-nginx.tmpl` | 检测 sqlmap/nmap/nikto/wpscan/nuclei 等通用扫描器的正则 |
| **AES-256 加密备份** | `backup.go` | `openssl enc -aes-256-cbc -pbkdf2` 加密关键目录 |
| **监控脚本模式** | phase5 5 个脚本 | 证书过期/磁盘/服务存活的 cron+邮件告警模板 |
| **Logrotate 模板** | `logrotate-myx.tmpl` | 通用日志轮转，可适配任意服务 |

### 不适合移植的

| 资产 | 原因 |
|------|------|
| defense daemon（Go 二进制） | 强依赖 xray error.log 的 `REALITY: processed invalid connection` 日志格式 |
| myx-defense.service systemd 单元 | 调用 `myx defense run`，XSG 没有 Go 二进制 |
| bg-traffic.sh | 生成代理混淆流量，XSG 无代理 |
| cert-monitor/service-monitor | 证书和服务名硬编码 |

## 二、竞品可借鉴点

GitHub 页面被墙无法直接抓取，基于搜索结果摘要分析：

| 竞品 | 可借鉴技术 | 对 XSG 的价值 |
|------|-----------|:--:|
| **du_setup** | SSH 自动回滚（改 sshd_config 后 `sshd -t` 失败自动恢复） | ⭐⭐⭐ 防止自锁 |
| **du_setup** | 配置修改前自动备份（`.bak` 文件 + 时间戳） | ⭐⭐⭐ 可回滚 |
| **du_setup** | 幂等性设计（重复运行不重复操作） | ⭐⭐ 友好 |
| **linux-ssh-init-sh** | 死锁检测（禁止锁自己的场景检测） | ⭐⭐⭐ 关键安全 |
| **linux-ssh-init-sh** | 自动化/无头模式（环境变量跳过交互） | ⭐⭐ 批量部署 |
| **hardening-ubuntu** | 预检清单（安装前打印将要执行的步骤） | ⭐⭐ 透明度 |
| **hardening-ubuntu** | 模块化拆分（每个功能独立脚本） | ⭐ 单文件更简单 |

### 最值得借鉴的 3 个技术

1. **SSH 自动回滚** — 改 sshd_config 后 `sshd -t && systemctl reload sshd`，失败则 `cp .bak` 恢复
2. **死锁检测** — 如果用户禁用了密码+禁用了 root+没配 SSH key → 拒绝执行，提示风险
3. **配置备份** — 每个被修改的系统文件改前 `cp "$f" "$f.bak.$(date +%s)"`

## 三、XSG 项目结构建议

```
XSG/
├── xsg.sh                    # 主脚本（单文件，bash，零依赖）
│
│   执行流程:
│   ┌─ Phase 0: OS/网络检测
│   ├─ Phase 1: 创建运维用户（SSH key 交互 + sudo + 密码）
│   ├─ Phase 2: 安全基线（UFW + SSH硬化 + Fail2ban + 禁服务）
│   ├─ Phase 3: 纵深防御（/tmp noexec + core dump + 模块黑名单 + auditd + rkhunter）
│   ├─ Phase 4: 系统优化（BBR + sysctl + limits + swap + DNS chattr）
│   └─ Phase 5: 运维设施（logrotate + 监控脚本 + 加密备份 + unattended-upgrades）
│
├── README.md                 # 用法 + 安全说明
└── LICENSE                   # MIT
```
